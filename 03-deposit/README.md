# 03 - 充值处理 + 7层防护

> 假充值是交易所最常见的攻击手段之一。本章实现了从 Receipt 校验到二次确认的完整 7 层防护链路，每层都有对应的测试用例验证其有效性。

## 7层防护一览

| 层级 | 防护点 | 攻击场景 |
|------|--------|----------|
| 第1层 | Receipt.Status 校验 | 发送失败交易，骗取交易所认为充值成功 |
| 第2层 | Transfer 事件日志校验 | 伪造 Transfer 事件结构 |
| 第3层 | Token 合约地址白名单 | 部署 symbol="USDT" 的假合约 |
| 第4层 | BlockHash 一致性 | 重组期间交易被打包到其他块 |
| 第5层 | 内部交易 Trace | 合约主调用失败但子调用有转账 |
| 第6层 | 交易方向分类过滤 | 将提现交易误判为充值 |
| 第7层 | 二次校验 | 节点层面的数据污染 |

## 生产差距

- 本 demo 不含布隆过滤器（生产中用于 O(1) 地址查找）
- 二次校验失败处理只有 Ignore 和 Alert，生产中还有 FuzzyCompare 模糊比对
- 生产中 Fee Token（如 SafeMoon）需要专门处理 burn fee，本 demo 不涉及
