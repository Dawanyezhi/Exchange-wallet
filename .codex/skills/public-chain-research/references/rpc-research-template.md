# RPC 调研模板

## 基础原则

RPC 调研不要只列接口名。必须说明：

- 官方节点是否原生支持。
- 是否需要开启归档、txindex、trace、event index、插件或额外模块。
- 是否能查历史数据。
- 是否能按任意地址查余额/交易。
- 是否适合生产记账。
- 不支持时用什么索引器或数据平台替代。

## 必查能力

| 能力 | 调研问题 | 钱包影响 |
|------|----------|----------|
| 同步状态 | 如何判断节点已同步、是否 IBD、当前高度和 header 高度 | 决定服务是否可入账/出账 |
| 最新区块 | 获取最新高度和 hash 的 RPC | 扫块入口 |
| 区块详情 | 是否能按高度/hash 拉完整交易 | 充值解析和重组检测 |
| 交易详情 | 是否能按 hash 查交易、receipt、状态、输入输出 | 二次校验 |
| 地址余额 | 是否支持任意地址余额 | 对账和风控 |
| 地址交易记录 | 是否支持任意地址历史 | 若不支持需自建索引 |
| 广播交易 | raw tx 广播接口、错误码、重复广播行为 | 提现状态机 |
| 费用估算 | gas/vB/资源费推荐接口 | 手续费预估 |
| Mempool | 未确认交易查询、替换、冲突检测 | RBF/卡交易处理 |
| Trace/Event | 内部交易、合约事件、失败交易识别 | 假充值防护 |
| 特殊 RPC | 链特有字段，如 memo、recent blockhash、rent、resource | 链特化逻辑 |

## 节点部署调研

必须覆盖：

- 推荐节点客户端和版本。
- 是否需要归档节点。
- 是否需要 txindex/trace/indexer。
- 磁盘、内存、CPU、网络粗略要求。
- RPC 鉴权和内网隔离。
- 是否需要双节点或多节点二次校验。
- 初始化同步和历史重扫策略。
- 节点落后、分叉、返回不一致时的停服/告警策略。

## 数据平台替代

如果官方节点不支持地址交易历史或 Token 索引，可调研：

- 官方或社区索引器。
- 主流浏览器 API。
- 第三方数据平台。
- 自建索引器方案。

但必须写清楚：第三方平台不能作为唯一记账来源，最多用于二次校验、补数据或运营查询，除非业务明确接受该信任边界。
