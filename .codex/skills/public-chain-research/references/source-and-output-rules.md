# 资料来源与输出规范

## 资料优先级

优先级从高到低：

1. 官方开发者文档。
2. 官方 RPC 文档。
3. 官方节点客户端文档。
4. 标准协议文档，例如 BIP、EIP、SLIP、CAIP。
5. 官方博客、事故复盘、治理论坛。
6. 主流浏览器和数据平台。
7. 社区文章和问答，只能作为辅助线索。

当信息可能变化时，必须联网确认，例如：

- 最新节点版本和 RPC 行为。
- 当前推荐确认数。
- 节点部署参数。
- 浏览器 API 能力。
- Token/NFT 协议状态。
- 费用市场和重组事件。

## 输出结构

完整调研报告建议使用：

1. 摘要结论。
2. 基础信息表。
3. 链类型和钱包影响。
4. 地址和密钥体系。
5. 交易构建和签名。
6. RPC 和节点部署。
7. 充值、提现、归集、对账设计。
8. 数据库表和状态机建议。
9. 费用模型。
10. 重组/finality 和历史风险。
11. Memo/Tag/Token/NFT 支持范围。
12. 生产安全清单。
13. 对当前项目的落地改造建议。
14. 参考资料链接。

## 必须明确的结论

每份报告最后必须回答：

- 是否建议接入该链。
- 首期最小支持范围是什么。
- 哪些能力不建议首期支持。
- 是否需要自建索引器。
- 充值确认数如何配置。
- 提现并发控制靠 Nonce、UTXO 锁还是其他机制。
- 回滚时需要恢复哪些业务表。
- 对账口径是什么。
- 生产上线前必须补哪些测试。

## 交易构建和签名案例验收

每份链调研必须包含一个生产级案例。交付前检查：

- 是否给出提现或归集的具体业务输入、链上状态输入和金额单位。
- 是否给出 unsigned tx/消息结构，而不只是“构造交易”。
- 是否列出签名服务入参、签名哈希构造依赖、签名结果格式和 key 定位方式。
- 是否明确签名前策略校验和签后 raw tx 反解析验签。
- 是否覆盖该链的并发控制：Nonce、UTXO 锁、sequence、recent blockhash、memo/tag 或等价机制。
- 是否说明广播、重复广播、加速/替换/取消、失败释放或不可释放条件。
- 是否说明 rawtx、签名审计、提现/归集状态、UTXO/Nonce 锁定等落库字段。

## 语言和风险表述

使用中文。不要把不确定内容写成事实。对资料中的事实和工程建议做区分：

- “官方文档说明...”用于已确认事实。
- “工程建议...”用于基于交易所钱包经验的建议。
- “需要进一步确认...”用于资料不足或版本可能变化的信息。

不要承诺 demo 代码可直接生产上线。对生产能力必须说明依赖、限制和风险。
