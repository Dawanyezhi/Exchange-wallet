## 1. 基础结论

先给一张表，便于快速判断是否适合交易所接入：

| 维度 | 结论 | 钱包影响 |
|------|------|----------|
| 链类型 | Account/UTXO/Tag/L2/其他 | 决定余额、回滚、提现和对账模型 |
| 共识/finality | PoW/PoS/BFT/Sequencer | 决定确认数和深度回滚策略 |
| 原生币精度 | decimals 或最小单位 | 必须使用整数，禁止 float64 |
| 地址体系 | 地址格式、网络前缀、校验 | 决定派生、入库长度和验址 |
| 签名算法 | secp256k1/ed25519/schnorr/其他 | 决定 keyman 和离线签名参数 |
| 交易模型 | Nonce/UTXO/sequence/memo | 决定并发控制和防重放 |
| RPC 能力 | 原生节点是否支持余额/交易查询 | 决定是否自建索引器 |
| 费用模型 | gas、vB、资源租赁、带宽 | 决定预估费和实际费核算 |
| Token/NFT | 原生协议或合约协议 | 决定充值解析和白名单 |
| Memo/Tag | 是否需要 | 决定用户地址分配模型 |

## 2. 链基础信息

必须调研：

- 主网名称、chain id/network id、测试网信息。
- 原生币 symbol、最小单位、精度。
- 出块时间、平均确认时间、finality 机制。
- 是否有主流官方节点客户端，是否有轻节点/归档节点差异。
- 是否有 L2、跨链桥或侧链依赖。

## 3. 账户模型

明确属于哪一类：

- Account：地址有余额和 Nonce，典型如 EVM、TRON。
- UTXO：余额是未花费输出集合，典型如 BTC、LTC、DOGE。
- Tag/Memo：共享地址加用户标签，典型如 XRP、XLM、ATOM、EOS。
- 多资产合约链：主币和 Token 解析路径不同。
- L2/桥接链：需要额外考虑 L1 finality、提现挑战期和桥风险。

说明对充值、提现、归集、对账、回滚的影响。

## 4. 地址体系

调研：

- 地址格式、长度、前缀、大小写敏感性、校验规则。
- 主网/测试网/合约地址是否可区分。
- 地址是否可从公钥直接推导，是否需要 account id、memo、tag 或 activation。
- 是否存在地址复用风险或最低激活余额。
- 数据库字段长度建议。

## 5. 密码学算法

调研：

- 曲线和签名算法：secp256k1、secp256r1、ed25519、Schnorr、BLS 等。
- 派生标准：BIP32/BIP44/BIP84/SLIP-0010/链自定义路径。
- 公钥格式：压缩/非压缩、x-only、ed25519 32 字节等。
- 签名结果格式：DER、65 字节 recoverable、compact、链自定义编码。
- 远程签名服务需要的参数，不要只写“签 32 字节 hash”，要列出签名哈希构造依赖。

## 6. 交易构建与签名

必须覆盖：

- unsigned tx 字段。
- 签名哈希构造。
- 防重放机制：chain id、nonce、sequence、recent blockhash、domain separator 等。
- 签名前策略校验：to、value、fee、memo、change、token contract、nonce/utxo 归属。
- 签后反解析和验签：确认 raw tx 中的输出、费用、链参数与预期一致。
- 广播、重发、加速、替换或取消机制。

## 7. Token、NFT、Memo/Tag

Token 调研：

- 是否原生支持 Token。
- Token 标准和事件模型。
- 充值解析依赖事件、余额变更、内部交易还是自定义索引。
- Token 精度是否从合约/RPC 获取，是否可变。
- 是否存在转账税、黑名单、暂停、rebase、反射型 Token 等异常行为。

Memo/Tag 调研：

- 是否强制 memo/tag。
- memo/tag 类型、长度、编码、是否大小写敏感。
- 漏填是否可找回，是否需要人工归集或人工入账流程。
- 入账唯一键应包含 `chain + tx_hash + log_index/output_index + memo/tag`。

NFT/铭文调研：

- 是否首期支持。
- 若不支持，明确防误花、防误归集、防误显示策略。

## 8. RPC 与节点

按 `rpc-research-template.md` 补齐，不要只列 RPC 名称，要说明节点是否原生支持、是否需要索引器、是否支持历史查询、是否可用于生产记账。

## 9. 费用模型

调研：

- 费用单位和精度。
- 预估费用与实际消耗的计算方式。
- 手续费上限、最小手续费、dust、资源租赁或带宽模型。
- 交易加速和替换机制。
- 归集小额资产是否经济。

输出应给出至少一个费用估算例子。

## 10. 重组与最终性

调研：

- 是否可能重组。
- finality 是概率性还是确定性。
- 推荐确认数，区分 demo、小额、普通、大额。
- 历史重组、停链、攻击或客户端事故。
- 超深重组处理：暂停入账/出账、告警、人工介入。

## 11. 浏览器和资料链接

优先列：

- 官方开发者文档。
- 官方 RPC 文档。
- 官方节点部署文档。
- 标准协议文档。
- 主流浏览器。
- CoinMarketCap 或 CoinGecko 链信息页。

## 12. 接入建议

固定输出：

- 是否建议接入。
- 最小上线能力。
- 首期不建议支持的能力。
- 当前项目需要新增的 `coinset` 配置。
- 需要新增或调整的数据表。
- 必须补充的测试。
- 生产风险和监控告警。
