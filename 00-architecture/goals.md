# 00 - 架构设计知识点层级

| 层级 | 知识点 |
|------|--------|
| **L3**（白板能讲） | 三层架构职责分离、热冷钱包隔离原则、为什么密钥管理层不能处理链上操作 |
| **L3** | SafeHeight 定义：`SafeHeight = 当前最高块 - 确认数`，SafeHeight 以上的充值不能归集、不能上账 |
| **L2**（看到能识别） | FeatureGate 配置驱动（位掩码组合特性）、多链抽象（Account/UTXO/Tag）|
| **L2** | 充值流 / 提现流 / 归集流的数据流向 |
| **L1**（知道有就行） | 各链的具体确认数配置数值（ETH=12，BSC=20，Polygon=400，ETC=500）|

## 自检问题

1. **为什么密钥层和钱包层要分离？**
   - 密钥服务一旦上线极少重启，降低私钥暴露时间
   - 最小权限原则：钱包服务只发送待签名数据，walletmanager 内部完成签名后返回签名结果，私钥从不出进程，不能访问主种子
   - 审计面缩小：密钥服务的网络策略更严格（只接受钱包服务的请求）

2. **Account 型和 UTXO 型的核心差异？**
   - Account：地址复用，余额是账户状态，Nonce 防重放，重组时只需回滚余额
   - UTXO：每笔交易消耗 UTXO，无 Nonce，重组时需要额外恢复 UTXO 集（revertUTXO）

3. **SafeHeight=100 时，能处理高度101的充值吗？**
   - 不能。高度101 > SafeHeight=100，说明该充值尚未获得足够确认，可能在重组中被撤销
