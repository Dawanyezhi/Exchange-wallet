# 01 - 密钥管理知识点层级

| 层级 | 知识点 |
|------|--------|
| **L3** | Scrypt 参数含义（N/r/p）：N=262144 需要 256MB 内存、单次 ~1s，使暴力破解成本极高 |
| **L3** | BIP32 派生路径：`m/purpose'/coin_type'/account'/change/index`，硬化派生（index ≥ 2^31）不可从公钥推导子私钥 |
| **L3** | 为什么要内存清除：DRAM 断电后残留数据（Cold Boot Attack），内存 dump 攻击 |
| **L3** | X25519 用于**密钥交换**，Ed25519 用于**数字签名**，两者不可混用 |
| **L2** | AES-CTR（流密码）vs AES-GCM（认证加密）：存储用 CTR+MAC（Web3 规范兼容），传输用 GCM（内置认证）|
| **L2** | 硬化派生 vs 非硬化派生：硬化派生泄漏子私钥不会暴露兄弟密钥；非硬化派生泄漏链码+子私钥可推导父私钥 |
| **L2** | XOR 掩码：私钥在内存中不以明文存放，`masked = key XOR random_mask`，使用时再还原 |
| **L1** | Scrypt 具体数值：N=2^18=262144，r=8，p=1，dklen=32 |
| **L1** | pbkdf2 的备选场景：移动端资源受限，Scrypt 内存占用过高时降级使用 |
| **L4** | Go 内存清除不可靠：编译器可能优化掉"无副作用"的清零代码，需要 `runtime.KeepAlive` 防止 GC 回收 |
| **L4** | MPC 如何彻底消除单点：DKG 后完整私钥从未在任何节点出现过 |

## 自检问题

1. **Scrypt N=2^18 的含义？**
   - 需要 256MB 内存（N × r × 128 字节 = 262144 × 8 × 128 = 256MB）
   - 单次计算约 1 秒（现代 CPU），暴力破解每秒最多尝试 1 个密码
   - 相比 bcrypt（2^14 轮），Scrypt 的内存硬性要求使 ASIC/GPU 加速效果差

2. **X25519 和 Ed25519 的区别？**
   - X25519 是 Curve25519 上的 ECDH 密钥交换，输出共享密钥，用于协商对称加密密钥
   - Ed25519 是 Twisted Edwards Curve 上的 Schnorr 签名，用于消息签名和验证
   - 两者底层曲线相关但参数不同，**不能把 Ed25519 私钥直接用于 X25519**

3. **为什么清除内存需要4步？**
   - 仅写0可能被编译器优化删除（因为变量之后未使用）
   - 写1、写随机数确保操作有"副作用"，迫使编译器保留
   - 最后再写0确保最终状态是清零
   - `runtime.KeepAlive` 防止 Go GC 在最后一次使用前提前回收
